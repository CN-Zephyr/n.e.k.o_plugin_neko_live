# 贡献授权协议（草案模板）

> 状态：Proposal / 草案，尚未生效。该模板不改变当前贡献规则，不因提交 PR、沉默、存在提交记录或出现团队署名而自动被接受。正式启用前须明确接收主体、接受方式和起始日期；历史贡献另行确认。

## 1. 贡献及当事人

贡献者：待填写个人姓名或组织法律主体及有效联系方式。

项目接收主体：待填写有权管理本项目授权的个人或法律主体，不仅填写团队简称。

贡献范围：待填写仓库、PR、提交、文件和明确排除内容。该范围应能标识实际作品，不能把贡献者未来全部作品或其他项目一并纳入。

## 2. 保留所有权与授权权限保证

贡献者保留其贡献的著作权及其他原有权利，本协议不要求版权转让。贡献者确认，对列明贡献具有作出下述授权所需的权利；属于职务作品、雇主所有或受其他协议约束时，应取得相应授权，不能仅以个人提交代替雇主同意。

贡献者应明确披露已知的第三方来源、相应许可和不能按本协议授权的内容。接收主体不得仅因接受贡献就声称拥有第三方代码、用户内容或素材。

## 3. 对接收主体的许可

在贡献者有权授权的范围内，贡献者向项目接收主体授予全球、非独占、免许可费、持续有效且不因其退出项目而单方撤回的著作权许可，以复制、修改、编译、展示、分发并再许可列明贡献及其修改版。

接收主体可以将列明贡献随本项目及其相关发行版，按以下一种或多种方式对外提供：

1. 项目正式采用的社区源码许可及其后续版本；
2. 接收主体与具体被授权方另行签署的商业或跨项目许可；
3. 接收主体另行决定的对外软件许可，但不得超出贡献者实际授予的权利或抹去适用第三方声明。

本条包含明示的商业再授权权限。贡献者接受本协议，不等于自动享有项目商业收入分成、雇佣关系、支持义务或项目决策权；若另有费用或分成约定，应另签书面协议。贡献者仍可自行使用和另行许可其有权处理的原创贡献。

## 4. 必要专利与声明

如贡献者有权许可、且实施其贡献或其与提交时本项目的组合所必需的专利请求项，贡献者就上述许可用途一并授予全球、非独占、免许可费的必要实施和再许可权。已知不能授予的权利须披露，由接收主体在合入前处理。

应保留实际作者、版权和适用第三方声明。标注“贡献给团队”或签署来源声明，不应被解释为对所有历史作者权利的统一转让。

## 5. 历史贡献与范围限制

本协议仅覆盖双方明确列出的贡献。历史代码需要另行取得本协议下的权限时，应由相应有权主体明确确认；不能用更新 CONTRIBUTING 或把本模板放进仓库的方式追溯代签。

本协议不撤销贡献此前按 MIT、Apache 等已经对外授予的权利，也不消除使用者根据既有许可取得的权利。接收主体对本项目整体采用其他条款时，仍须遵守来源和历史许可义务。

## 6. 接受、记录与隐私

可采用经确认的电子签署、明确同意文本或其他具有证据力的方式接受。应记录贡献范围、协议版本、接收主体、同意时间及必要的签署权限；单独勾选 DCO 或提交 Signed-off-by 不替代本协议中的商业再授权。

仅保存授权管理所需的最少个人信息。联系方式和权利文件应由授权管理人员妥善保管，不应要求在公开 PR、日志或仓库中暴露证件、住址或其他敏感资料。

## 7. 启用前确认与签署

须补齐接收主体、有效通知方式、准据法、争议解决及适用的强制性条款，并完成法律审阅。未接受本协议的贡献仍依原有效约定处理，不能宣称已经取得本协议全部权限。

贡献者及有权签署人：待填写；签署日期：待填写。

项目接收主体及有权签署人：待填写；签署日期：待填写。

贡献范围附件：待填写。协议正文、范围附件和接受记录须保持可追溯关联。
