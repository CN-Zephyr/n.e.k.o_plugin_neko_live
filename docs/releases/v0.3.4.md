# 直播助手 v0.3.4

本版本新增弹幕点歌，修复观众记忆写入宿主时一律被拒绝的问题，并让自动营业和空闲营业在有弹幕排队时让路。许可证改为 AGPL-3.0-or-later。

## 变更

- 弹幕点歌（`song_request`，默认关闭）：观众发送“点歌 晴天”这类触发弹幕，歌曲会加入 `custom_music_list` 插件的播放列表，NEKO 口头回应结果。触发词、权限档位（所有人 / 粉丝 / 舰长）和按 UID 的冷却可在面板“直播间互动”的“点歌”卡片里设置；卡片列出本场最近 50 条记录，可把某首插队到当前歌曲之后。未安装音乐插件时卡片置灰。见 [song_request 模块文档](../modules/song_request.md)。
- 观众记忆写入修复：此前写入宿主 `scoped_history` 时一律返回 HTTP 422，因为带幂等键的请求缺少 `subject_epochs`。现在每个新批次先读取服务端清除代数，重试沿用同一代数；代数读不到时保留批次到下次提交，写入被 422 拒绝时丢弃该批并记录原因，不再无限重试。见 [viewer_stores 文档](../modules/viewer_stores.md)。
- 主持让路：`live_events` 择优窗口打开或有缓冲弹幕时，自动营业和空闲营业本轮不开口（Skip Reason `active_engagement.danmaku_pending`）。自动营业在回完弹幕后的等待时间：standard 45 秒改为 90 秒，active 30 秒改为 60 秒，quiet 保持 210 秒。
- 失败可见性：pipeline 探针和插件入口出错时仍走原有的安全默认值，但会记录一条只含异常类型的 warning，不记录异常消息。CI 新增 `panel_compat.tsx` 与模块化源文件的一致性检查。
- 许可证：本版本起按 AGPL-3.0-or-later 提供，见根目录 `LICENSE` 与 `NOTICE`。v0.3.2 与 v0.3.3 已取得的权利继续有效。

## 升级与边界

- 内部插件 id `neko_live`、配置及数据目录不变，无需迁移。点歌默认关闭，不开启时触发弹幕按普通弹幕处理。
- 不打断正在播放的主持语音：弹幕在主持语音开始之后才到达时，仍要等这句播完。
- 观众记忆写入每个新批次多一次本机 GET，没有新增轮询或定时器。宿主侧的观众记忆召回尚未实现。
- 点歌需要同时安装 `custom_music_list` 插件；跨插件只调用其入口，不读其文件或 HTTP 接口。

## 验证

- 本地全量 Python 回归：2484 passed、1 skipped；跳过项为 Windows 上的 POSIX 权限检查。
- 插件检查 0 error；用同步后的宿主 memory_server 校验观众记忆写入请求可以通过并得到预期确认。
- 离线检查不代表真实平台连接、模型回答、真实 `custom_music_list` 进程或 Electron 音频播放已验收；点歌、记忆写入和主持让路都还需要真实直播复测。
